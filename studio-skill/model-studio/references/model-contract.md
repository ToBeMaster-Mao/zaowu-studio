# 平台模型契约

## 入口

`model.js` 是浏览器 ES Module。它必须导出无参数的 `createModel()` 函数。该函数创建并返回：

```js
import * as THREE from 'three';

export function createModel() {
  const root = new THREE.Group();
  root.name = 'model';

  const body = new THREE.Mesh(
    new THREE.BoxGeometry(1, 1, 1),
    new THREE.MeshStandardMaterial({ color: 0xe8ebef }),
  );
  body.name = 'body';
  root.add(body);

  return { root, animations: [] };
}
```

示例只展示入口契约，不是替换已有模型的模板。`root` 可以是 `Group` 或其他 `Object3D`。无动画时可省略 `animations`。

## 职责和依赖

平台负责创建场景视口、相机、灯光、交互和导出。模型入口只返回模型内容，不创建 `WebGLRenderer`、DOM 元素、事件监听器或独立动画循环。

只导入 `three` 或工程明确批准的 `three/addons/` 模块。不加入 CDN URL、任意包或网络请求；不读取本地文件、凭据或环境变量。模型处于浏览器沙箱中，不能依赖 Node.js API。使用纹理或已有资源时，先检查该工程实际支持的资产路径和加载机制，不自行假定新协议。

## 局部编辑

节点名称和已存在的部件 ID 是定位依据。修改几何后保留对应标识，避免通过随机值、时间戳或数组位置生成不稳定名称。已有 `userData` 字段继续保留；没有统一字段时，不臆造平台必然识别的新字段。

先读现有构造逻辑再改。对多次出现的部件明确区分：用户要求一个窗户，还是整排窗户；以用户描述、选中对象和画面一起判断。选中对象无法唯一定位且会影响修改范围时，说明歧义。

改变尺寸时注意父节点缩放、局部坐标和世界坐标。材料、几何被多个网格共用时，确认修改应作用于所有实例；只改一个实例时按需要克隆资源。为透明面、机身贴附细节等处理重叠闪烁，避免单纯抬高到明显悬空。

动画沿用 `AnimationClip` 和稳定节点名称。不得为无关改动移除已有动画、骨骼或蒙皮权重。自动绑定骨骼并非本技能提供的能力；需要时先评估工程实际工具和用户需求。

## 验证边界

最低限度检查导入、语法、返回值和模型对象是否符合现有加载器。若工程已有渲染验证或 GLB 回读检查，复用它们。视觉检查重点为本次修改处、整体轮廓、错误遮挡和明显悬空。

平台出现校验失败时，根据真实错误修复本次代码。不要绕过沙箱或修改验证器来让错误消失。不能启动预览时，说明哪些代码检查已完成、哪些视觉结果尚未确认。
